# 识别优化记录 - 2026-05-12

## 背景

项目已在 2026-05-11 晚间和 2026-05-12 早间完成两次正式运行，邮件可正常收到，`data/frames` 和 `data/clips` 中生成了关键帧与证据视频。

观察到的问题：

- 每个时间窗会生成 5 张截图，其中 `best_brush` 和 `best_facewash` 易理解，另外 3 张 `frame_*.jpg` 看起来没有人。
- 2026-05-12 早间的 `best_brush` 实际是洗脸动作，`best_facewash` 正确。
- 2026-05-11 晚间的 `best_brush` 正确，`best_facewash` 实际是走路。
- 2026-05-11 的两段视频中人物坐着，没有刷牙或洗脸。
- 2026-05-12 的两段视频中人物在饮水机倒水，没有刷牙或洗脸。

## 结论

另外 3 张 `frame_*.jpg` 是采集器在时间窗开始后保存的前 3 张采样帧，仅用于调试和留样，不代表行为证据。真正的行为证据帧是 `best_brush` 和 `best_facewash`。

误识别主要来自两个方面：

- 行为连续段状态机存在缺陷：某一帧误触发刷牙或洗脸后，普通的后续非动作帧不会正常结束该动作段，导致证据视频截到后面的坐着、倒水等画面。
- 刷牙和洗脸规则过宽：洗脸时手指靠近嘴部会被刷牙规则命中；洗脸的单手腕兜底也容易把走路、抬手、喝水等动作误判为洗脸。

## 本次改动

### 1. 修正行为连续段结束逻辑

修改文件：`analyzer/behavior_rules.py`

- 新增 `last_brush_seen` 和 `last_facewash_seen`，用最后一次真实检测到动作的时间作为动作段结束点。
- 后续非动作帧超过 `break_seconds` 后，会正确关闭当前动作段。
- `finalize()` 不再把一个误触发动作延伸到整个时间窗结束。
- 新增 `min_segment_seconds`，默认忽略少于 2 秒的短暂误触发。

### 2. 洗脸优先，避免同一帧同时计入刷牙

修改文件：`analyzer/behavior_rules.py`

- 同一帧先判定洗脸。
- 若判定为洗脸，则该帧不再计入刷牙。
- 解决洗脸动作中手指靠近嘴部时，被 `best_brush` 抢走的问题。

### 3. 收紧刷牙与洗脸规则

修改文件：`analyzer/behavior_rules.py`

- 刷牙：如果已经检测到手部指尖，但指尖没有靠近嘴部，则不再使用手腕距离强行兜底。
- 洗脸：优先要求两只手都有多个指尖靠近面部。
- 洗脸：去掉“单只手腕非常靠近面部也算洗脸”的高噪声兜底。

### 4. 保留左右手分组信息

修改文件：`analyzer/hands_detector.py`

- 新增 `get_finger_tip_groups()`，按每只手返回指尖坐标。
- 洗脸规则可以区分“两只手都在脸附近”和“单只手靠近脸”。

### 5. 只从真实动作帧中选择 best 截图

修改文件：`analyzer/behavior_analyzer.py`

- `best_brush` 只在当前帧真实触发刷牙时更新。
- `best_facewash` 只在当前帧真实触发洗脸时更新。
- 避免普通人脸、手部或姿态帧被选为最佳证据。

### 6. 增加配置项和回归测试

修改文件：

- `config.yaml`
- `tests/test_behavior_rules.py`

新增配置：

```yaml
analysis:
  min_segment_seconds: 2.0
```

新增测试覆盖：

- 单次误触发不会延伸到时间窗结束。
- 洗脸触发时不会同时计入刷牙。

## 后续建议

下一步建议启用 ROI：

```yaml

  enabled: true
```

然后将 `sink_area` / `mirror_area` 配置为洗手台和镜子区域。这样倒水机、走路、坐着等非洗漱区域动作会被过滤掉，是降低误报最有效的下一步。

本次改动后建议继续观察 2-3 个早晚时间窗，再根据实际截图微调：

- `hands.brush_finger_threshold`

- `analysis.min_segment_seconds`

## 2026-05-13 追加优化

### 背景

2026-05-12 晚间邮件结果为：

- 刷牙：好，约 102 秒连续刷牙动作
- 洗脸：中，约 21 秒

实际证据图中人物没有刷牙或洗脸。

2026-05-13 早间邮件结果为：

- 刷牙：差，约 39 秒
- 洗脸：未完成

实际证据图中人物没有刷牙或洗脸，但孩子反馈早上确实完成了刷牙洗脸。

复查日志发现，2026-05-12 晚间和 2026-05-13 早间的分析启动时仍显示 `ROI=False`。同时当时 `sink_area` 还是全画面 `[0.0, 0.0, 1.0, 1.0]`，即使启用 ROI 也没有实际过滤效果。

### 判断

这轮问题主要不是视觉模型精度不足，而是当前规则仍偏“几何接近”：

- 手指贴近嘴会被当成刷牙。
- 双手或手腕靠近脸会被当成洗脸。
- 没有限制人物必须出现在洗漱有效区域。
- 没有要求动作片段具备刷牙/洗脸所需的连续运动。

### ROI 标定

修改 `config.yaml`：

```yaml
roi:
  enabled: true
  sink_area: [0.84, 0.04, 1.0, 0.92]
  mirror_area: null
  body_area: null
```

该区域基于 2026-05-12/13 的证据帧做第一版标定：保留画面右侧洗漱位/人物区域，排除中间柜子、椅子、饮水机等容易误触发的区域。

### 规则升级

修改文件：

- `analyzer/behavior_rules.py`
- `analyzer/behavior_analyzer.py`
- `config.yaml`
- `tests/test_behavior_rules.py`

新增片段验证：

- 单次或短时误触发不计入结果。
- 候选片段需要至少 `min_segment_hits` 次命中。
- 候选片段需要具备最小运动幅度，静态手贴嘴、摸脸不再算作刷牙/洗脸。
- `best_*` 证据帧只从最终接受的动作片段中选择，避免保存被规则拒绝的误触发画面。

新增配置：

```yaml
analysis:
  min_segment_seconds: 5.0
  min_segment_hits: 8
  brush_min_motion: 0.020
  facewash_min_motion: 0.025

hands:
  brush_finger_threshold: 0.075
  brush_wrist_threshold: 0.12
  face_finger_threshold: 0.10
  face_wrist_threshold: 0.15
```
