# 小米摄像机洗漱行为监督系统 — 迁移部署指南

本文档描述如何将本项目完整迁移到另一台电脑并重新部署运行。包含旧电脑数据打包、新电脑环境配置、项目部署、服务验证等全部步骤。

> **适用场景**：Windows 11 + WSL Ubuntu 24.04（项目验证环境）。如果你的新电脑是原生 Linux，可跳过 WSL 相关步骤，直接使用 Docker 部署。

---

## 一、迁移前准备（旧电脑）

### 1.1 确认需要迁移的内容

本项目中有两类文件：**代码**（已纳入 Git）和 **本地运行时数据**（被 `.gitignore` 排除）。迁移时必须同时带走。

| 类别 | 路径 | 说明 | 是否必须 |
|------|------|------|---------|
| 项目源码 | `<repo-root>/` | 含已修补的 Dockerfile、docker-compose.yml、代码 | ✅ 必须 |
| 环境配置 | `<repo-root>/.env` | 密码、摄像头 DID、SMTP 等全部敏感配置 | ✅ **最重要** |
| AI 模型 | `<repo-root>/analyzer/models/*.task` | Pose + Hands 模型，约 44MB | ⚠️ 建议带走，也可重新下载 |
| 分析数据库 | `<repo-root>/data/db/app.db` | 历史评分记录 | ⚠️ 如需保留历史则带走 |
| 证据文件 | `<repo-root>/data/frames/` `data/clips/` | 历史关键帧和片段 | ❌ 通常不带走（体积大） |
| Miloco 证书 | `<repo-root>/miloco/cert/` | HTTPS 自签名证书 | ❌ 新电脑会自动重新生成 |
| Miloco 缓存 | `<repo-root>/miloco/miloco.db` `miot_cache/` | 设备信息和规格缓存 | ❌ 新环境会自动重建 |
| go2rtc 配置 | `<repo-root>/go2rtc/go2rtc.yaml` | 流名称配置 | ✅ 建议带走 |

### 1.2 打包项目

在旧电脑的 Ubuntu（WSL）中执行：

```bash
# 进入项目目录
cd ~/projects/micam-wsl-migration-20260322-211110

# 确认 .env 存在
ls -la .env

# 打包整个项目（包含被 git 忽略的本地文件）
tar -czf ~/micam-project-migration.tar.gz \
    --exclude='./.git' \
    --exclude='./data/frames' \
    --exclude='./data/clips' \
    --exclude='./miloco/images' \
    --exclude='./miloco/log' \
    --exclude='./__pycache__' \
    --exclude='./*.pyc' \
    .

# 查看打包结果
ls -lh ~/micam-project-migration.tar.gz
```

> **说明**：上面排除了 `data/frames` 和 `data/clips`，因为它们可能很大。如果你需要保留历史证据，把这两行 `--exclude` 删掉。

### 1.3 传输到新电脑

选择任意方式将 `micam-project-migration.tar.gz` 传到新电脑：

- 局域网共享 / U 盘
- `scp` / `rsync`
- 网盘

```bash
# 示例：局域网 scp 传输
scp ~/micam-project-migration.tar.gz user@新电脑IP:~/
```

## 二、新电脑环境准备

### 2.1 硬件与系统前提

| 项目 | 最低要求 | 推荐配置 |
|------|---------|---------|
| 系统 | Windows 11 + WSL Ubuntu 24.04 | 同上 |
| CPU | 4 核 8 线程（如 i7-7700 / R5-3500U） | i3-13100F 及以上 |
| 内存 | 8GB | 16GB+ |
| 磁盘 | SSD，剩余 10GB+ | SSD，剩余 50GB+ |
| 网络 | 与小米摄像机同一局域网 | 有线网络优先 |

> 不需要独立显卡，AI 推理为纯 CPU 运算。

### 2.2 安装 WSL 和 Ubuntu 24.04

在新电脑管理员 PowerShell 中：

```powershell
# 安装 WSL（如果尚未安装）
wsl --install

# 安装 Ubuntu 24.04
wsl --install -d Ubuntu-24.04

# 安装完成后重启电脑，然后设置 Ubuntu 用户名密码
```

### 2.3 配置 WSL 网络为 mirrored

新建或编辑 `C:\Users\<你的Windows用户名>\.wslconfig`：

```ini
[wsl2]
networkingMode=mirrored
dnsTunneling=false
firewall=true
autoProxy=false
```

保存后执行：

```powershell
wsl --shutdown
```

重新打开 Ubuntu 终端，验证拿到局域网 IP：

```bash
ip addr
```

预期应看到类似 `192.168.1.x/24` 的地址，**不应**是 `172.x.x.x`。

### 2.4 配置 Windows / Hyper-V 防火墙

在**管理员 PowerShell** 中执行：

```powershell
Set-NetFirewallProfile -Profile Domain,Private,Public -Enabled True
Set-NetFirewallHyperVVMSetting -Name '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -DefaultInboundAction Allow
Set-NetFirewallHyperVVMSetting -Name '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -DefaultOutboundAction Allow
New-NetFirewallHyperVRule -Name 'WSL-HyperV-Allow-In' -DisplayName 'WSL HyperV Allow In' -Direction Inbound -VMCreatorId '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -Protocol Any -Action Allow
New-NetFirewallHyperVRule -Name 'WSL-HyperV-Allow-Out' -DisplayName 'WSL HyperV Allow Out' -Direction Outbound -VMCreatorId '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -Protocol Any -Action Allow
wsl --shutdown
```

### 2.5 处理 Docker Desktop（重要）

项目要求使用 **WSL 内原生 Docker**，不能让 Docker Desktop 接管 Ubuntu。

如果已安装 Docker Desktop：

1. 打开 Docker Desktop → `Settings → Resources → WSL Integration`
2. 关闭 `Enable integration with my default WSL distro`
3. 关闭 `Ubuntu-24.04`
4. 点击 `Apply & Restart`
5. 完全退出 Docker Desktop（右键托盘图标 → Quit）

> 后续部署和运行时，**不要再打开 Docker Desktop 接管 Ubuntu**。如果误开了，先退出 Docker Desktop，再执行 `wsl --shutdown`。

### 2.6 在 Ubuntu 中安装原生 Docker

打开 Ubuntu 终端，进入你放置 tar.gz 的目录（如 `~/`），先安装 Docker：

```bash
# 如果项目已经解压，可以直接运行项目自带的安装脚本
cd ~
tar -xzf micam-project-migration.tar.gz -C ~/projects/micam-wsl/
cd ~/projects/micam-wsl
bash ./setup-native-docker.sh
```

脚本执行完成后，**关闭当前终端，重新打开一个新的 Ubuntu 终端**，验证：

```bash
docker version
docker compose version
docker context ls
ip addr
```

预期结果：
- `docker context ls` 当前是 `default *`
- `ip addr` 里有局域网 IP（如 `192.168.1.x`）
- `docker version` 和 `docker compose version` 正常输出

## 三、项目部署

### 3.1 解压项目（如果还没解压）

```bash
mkdir -p ~/projects && cd ~/projects
tar -xzf ~/micam-project-migration.tar.gz -C micam-wsl
cd micam-wsl
```

### 3.2 检查关键配置文件

#### 3.2.1 `.env`（最重要）

```bash
cat .env
```

确认以下字段正确：

```env
# 米家 / Miloco 配置
MILOCO_BASE_URL=https://localhost:8000
MILOCO_PASSWORD=<你的 Miloco 密码 MD5>
CAMERA_ID=<你的摄像机 DID>
RTSP_URL=rtsp://localhost:8554/your_stream1
VIDEO_CODEC=hevc
MIOT_LAN_TARGETS=<摄像机局域网 IP，如 192.168.1.50>

# 邮件通知（如果需要）
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=your_email@example.com
SMTP_PASSWORD=your_app_password
EMAIL_FROM=your_email@example.com
EMAIL_TO=recipient@example.com
SMTP_USE_TLS=true

# 时区
TZ=Asia/Shanghai
```

> **注意**：如果新电脑的局域网网段变了（比如从 `192.168.1.x` 变成 `192.168.31.x`），需要同步修改 `MIOT_LAN_TARGETS` 和小米摄像机的网络位置。

#### 3.2.2 `go2rtc/go2rtc.yaml`

```bash
cat go2rtc/go2rtc.yaml
```

如果有自定义流配置，确认流名称与 `.env` 中的 `RTSP_URL` 匹配。

#### 3.2.3 `config.yaml`

```bash
cat config.yaml
```

确认分析时间窗、评分阈值、模型选择等参数符合你的需求。如果新电脑性能较弱，可将模型降级：

```yaml
analysis:
  pose_model: "lite"   # 或 "full" / "heavy"
```

### 3.3 准备 AI 模型

检查模型文件是否已从旧电脑带过来：

```bash
ls -lh analyzer/models/
```

如果模型文件缺失（或被排除了），重新下载：

```bash
bash scripts/download_models.sh
```

如果需要使用 **Heavy** 模型（精度最高）：

```bash
curl -L -o analyzer/models/pose_landmarker_heavy.task \
    "https://storage.googleapis.com/mediapipe-models/pose_landmarker/pose_landmarker_heavy/float16/latest/pose_landmarker_heavy.task"
```

然后在 `config.yaml` 中确认：

```yaml
analysis:
  pose_model: "heavy"
```

### 3.4 创建运行时数据目录

```bash
mkdir -p data/frames data/clips data/db
mkdir -p miloco/cert miloco/miot_cache
```

如果需要恢复旧电脑的历史数据库：

```bash
# 假设旧数据库也在 tar.gz 里
cp data/db/app.db data/db/app.db.bak.$(date +%Y%m%d) 2>/dev/null || true
```

### 3.5 构建并启动服务

首次部署必须构建镜像：

```bash
# 构建 Miloco（需要从 GitHub 下载源码并打补丁，耗时较长）
docker compose build miloco

# 构建 analyzer（含 MediaPipe 和 OpenCV 依赖）
docker compose build analyzer

# 启动全部服务
docker compose up -d
```

如果只是重启（镜像已构建好）：

```bash
docker compose up -d
```

查看容器状态：

```bash
docker compose ps
```

预期应看到 4 个容器：
- `miloco`
- `go2rtc`
- `micam1`
- `analyzer`

## 四、验证部署

### 4.1 验证核心服务

```bash
# Miloco HTTPS 服务
curl -kI https://localhost:8000/login

# go2rtc 服务
curl -I http://localhost:1984
```

预期：
- `https://localhost:8000/login` 返回 HTTP 405 或正常响应（说明 HTTPS 服务已启动）
- `http://localhost:1984` 返回 HTTP 200 OK

### 4.2 验证视频桥接

```bash
# 查看 micam 日志
docker compose logs --tail 80 micam1
```

正常日志应包含：

```
Login successful
WebSocket connected. Streaming data...
Keyframe detected! Starting stream...
```

如果反复出现 `Data received timeout` 或 `PPCS_Connect errorcode: -3`，请检查：
1. 防火墙规则是否已生效
2. WSL 是否为 `mirrored` 模式
3. Docker Desktop 是否误接管了 Ubuntu
4. 摄像机和电脑是否在同一局域网

### 4.3 浏览器访问

| 地址 | 用途 |
|------|------|
| `https://localhost:8000` | Miloco 控制台（本机访问） |
| `https://<新电脑局域网IP>:8000` | Miloco 控制台（局域网其他设备） |
| `http://<新电脑局域网IP>:1984` | go2rtc 预览页 |

**浏览器建议**：优先使用 **Chrome**。Edge 可能出现解码失败或画面显示异常。

### 4.4 验证分析器

分析器在每天的 06:30–07:30 和 21:30–22:30 自动运行。你可以手动触发一次测试：

```bash
# 进入 analyzer 容器执行测试
# 或者直接在宿主机运行（需要 Python 环境）
python3 scripts/test_analysis.py
```

测试成功后会收到一封带附件的邮件（如果邮件配置正确）。

查看分析器日志：

```bash
docker compose logs --tail 50 analyzer
```

## 五、常见问题排查

### 5.1 Miloco 页面显示“设备已离线”

排查顺序：

```bash
# 1. 检查 Docker context
docker context ls
# 必须是 default *，不能是 desktop-linux

# 2. 检查 WSL 网络
ip addr
# 必须是 192.168.x.x，不能是 172.x.x.x

# 3. 检查防火墙
# 在 Windows PowerShell（管理员）重新执行 2.4 节的防火墙命令

# 4. 检查 MIOT_LAN_TARGETS
grep MIOT_LAN_TARGETS .env
# 确认 IP 是当前摄像机的实际局域网 IP
```

### 5.2 `docker context` 变成了 `desktop-linux`

```bash
# 切回 default
docker context use default

# 如果命令不存在，说明装的是 Docker Desktop 的命令行
# 请退出 Docker Desktop，运行 setup-native-docker.sh
```

### 5.3 本机访问 `https://<局域网IP>:8000` 不稳定

这是 WSL mirrored 的正常现象。**本机请始终使用 `https://localhost:8000`**。局域网其他设备才用 `https://<局域网IP>:8000`。

### 5.4 浏览器提示证书不安全

Miloco 使用自签名 HTTPS 证书，点击浏览器「高级 → 继续前往」即可。如果要消除警告，可自行替换 `miloco/cert/` 下的证书。

### 5.5 前端放大视频只显示一半

当前项目代码已修补此问题。如果仍看到旧效果：

- 按 `Ctrl + F5` 强制刷新
- 或打开无痕窗口重新访问

## 八、纯 Linux 环境部署（无 WSL）

如果你的新电脑是原生 Linux（如 Ubuntu Desktop / Server），步骤更简单：

```bash
# 1. 安装 Docker
sudo apt-get update
sudo apt-get install -y docker.io docker-compose-v2
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
# 重新登录用户

# 2. 解压项目
cd ~
tar -xzf micam-project-migration.tar.gz -C micam-wsl
cd micam-wsl

# 3. 检查 .env 和模型
ls -la .env analyzer/models/

# 4. 构建并启动
docker compose build miloco analyzer
docker compose up -d

# 5. 验证
docker compose ps
curl -kI https://localhost:8000/login
```

> Linux 原生环境不需要配置 WSL 和 Hyper-V 防火墙，但同样需要确保电脑和摄像机在同一局域网。
