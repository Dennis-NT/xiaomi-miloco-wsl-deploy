# Xiaomi Miloco + Micam 再次部署指南

## 1. 文档目的

这份文档记录了这次在 `Windows + WSL Ubuntu 24.04` 环境下，成功部署 `Miloco + Micam + go2rtc` 的完整过程、前提条件、关键命令、踩过的坑和复查办法。

如果后续需要再次部署，强烈建议直接以当前仓库根目录作为基线继续使用，因为这个目录里的代码和配置已经包含了本次排障后的修补。


## 2. 最终成功环境

- Windows 主机 IP：`<Windows-LAN-IP>`
- 摄像机 IP：`<Camera-LAN-IP>`
- WSL 发行版：`Ubuntu-24.04`
- Docker 运行方式：`WSL 内原生 Docker Engine`
- WSL 网络模式：`mirrored`
- Miloco 访问地址：
  - 本机 Windows：`https://localhost:8000`
  - 其他局域网设备：`https://<Windows-LAN-IP>:8000`
- go2rtc 地址：
  - 本机 / 局域网：`http://<Windows-LAN-IP>:1984`


## 3. 成功部署前提

### 3.1 必须满足

- 摄像机和这台 Windows 主机在同一局域网
- 摄像机在米家 App 中在线
- WSL 使用 `mirrored` 网络模式
- Windows 防火墙 / Hyper-V 防火墙允许 WSL mirrored 网络流量
- 不要让 `Docker Desktop` 接管这套 Ubuntu 发行版
- Ubuntu 中使用原生 `docker`，而不是 `desktop-linux` context

### 3.2 强烈建议

- 浏览器优先用 `Chrome`
- 同一台 Windows 主机访问 Miloco 时优先用 `https://localhost:8000`
- 使用当前项目目录中的已修补代码，不要直接重新用原始 tar 包裸跑


## 4. 关键结论

### 4.1 这套环境最稳的组合

`WSL mirrored + WSL 原生 Docker + Hyper-V 防火墙放行 + Docker Desktop 不接管 Ubuntu`

### 4.2 不推荐的组合

`Docker Desktop 集成 Ubuntu + Docker Desktop 容器网络 + WSL NAT`

这个组合下，最容易出现：

- `设备已离线`
- `PPCS_Connect errorcode: -3`
- `micam Data received timeout`


## 5. Windows 侧准备

### 5.1 WSL 网络配置

文件：

`C:\Users\<YourUser>\.wslconfig`

建议内容：

```ini
[wsl2]
networkingMode=mirrored
dnsTunneling=false
firewall=true
autoProxy=false
```

改完后在 `Windows PowerShell` 执行：

```powershell
wsl --shutdown
```

重新打开 Ubuntu 后，用下面命令确认已经拿到局域网 IP：

```bash
ip addr
```

预期应该看到 `192.168.1.x/24` 这一类地址，而不是 `172.23.x.x`。


### 5.2 Docker Desktop 的正确处理方式

可以保留安装，但不要接管这套 Ubuntu。

在 Docker Desktop 中：

1. `Settings -> Resources -> WSL Integration`
2. 关闭 `Enable integration with my default WSL distro`
3. 关闭 `Ubuntu-24.04`
4. `Apply & Restart`
5. 最后直接 `Quit Docker Desktop`

注意：

- 后续部署和运行时，不要再把 Docker Desktop 打开并接管这套 Ubuntu
- 如果误开了 Docker Desktop，先退出，再执行一次 `wsl --shutdown`


### 5.3 Windows / Hyper-V 防火墙

本次最关键的坑之一就是这里。

现象：

- 米家 App 里摄像机在线
- Miloco 里却显示 `设备已离线`
- 关闭 Windows 防火墙后立刻恢复

说明问题不在项目本身，而在 `WSL mirrored` 下的防火墙拦截。

在“管理员 PowerShell”里执行：

```powershell
Set-NetFirewallProfile -Profile Domain,Private,Public -Enabled True
Set-NetFirewallHyperVVMSetting -Name '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -DefaultInboundAction Allow
Set-NetFirewallHyperVVMSetting -Name '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -DefaultOutboundAction Allow
New-NetFirewallHyperVRule -Name 'WSL-HyperV-Allow-In' -DisplayName 'WSL HyperV Allow In' -Direction Inbound -VMCreatorId '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -Protocol Any -Action Allow
New-NetFirewallHyperVRule -Name 'WSL-HyperV-Allow-Out' -DisplayName 'WSL HyperV Allow Out' -Direction Outbound -VMCreatorId '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -Protocol Any -Action Allow
```

执行后建议再做一次：

```powershell
wsl --shutdown
```

说明：

- 这里的 `VMCreatorId` 是本次环境里实际使用成功的值
- 如果后续环境变化，建议用 `Get-NetFirewallHyperVVMSetting` 和 `Get-NetFirewallHyperVRule` 再确认一次


## 6. Ubuntu 侧准备

### 6.1 安装 WSL 原生 Docker

如果 Ubuntu 里还没有原生 Docker，可以直接运行：

```bash
bash ./setup-native-docker.sh
```

脚本路径：

`<repo-root>/setup-native-docker.sh`

脚本完成后，关闭当前 Ubuntu 终端，再打开一个新的终端，执行：

```bash
docker version
docker compose version
docker context ls
```

预期：

- `docker version` 正常
- `docker compose version` 正常
- `docker context ls` 当前为 `default *`
- 不是 `desktop-linux`


### 6.2 Docker 服务确认

```bash
systemctl status docker --no-pager
```

应看到 `active (running)`。


## 7. 项目部署步骤

### 7.1 解压项目

原始 `部署.txt` 内容很短，但实际环境里不够完整。

原始步骤：

```bash
cd ~
mkdir -p ~/projects && cd ~/projects
tar -xzf ~/your-project.tar.gz
cd <repo-root>
ip addr
sed -n '1,120p' .env
docker compose build miloco
docker compose up -d
docker ps
curl -k https://localhost:8000/login
```

真正推荐的可复用步骤如下。


### 7.2 进入项目目录

```bash
cd <repo-root>
```


### 7.3 确认 `.env`

当前成功配置如下：

```env
MILOCO_BASE_URL=https://localhost:8000
MILOCO_PASSWORD=<你的 miloco 密码 md5>
CAMERA_ID=<你的摄像机 DID>
RTSP_URL=rtsp://localhost:8554/your_stream1
VIDEO_CODEC=hevc
STREAM_CHANNEL=0
MILOCO_PORT=8000
MILOCO_HOST=0.0.0.0
MILOCO_LOG_LEVEL=warning
MIOT_LAN_TARGETS=<Camera-LAN-IP>
TZ=Asia/Shanghai
```

重点说明：

- `MILOCO_BASE_URL` 用 `https://localhost:8000`
- `RTSP_URL` 用 `rtsp://localhost:8554/your_stream1`
- `VIDEO_CODEC` 对这类 3K 机型通常应先尝试 `hevc`
- `MIOT_LAN_TARGETS` 填摄像机 LAN IP


### 7.4 构建并启动

首次或前端有改动时：

```bash
docker compose build miloco
docker compose up -d
```

如果只是重启运行：

```bash
docker compose up -d
```


### 7.5 验证容器

```bash
docker compose ps
```

应看到：

- `miloco`
- `go2rtc`
- `micam1`


### 7.6 验证服务

```bash
curl -kI https://localhost:8000/login
curl -I http://localhost:1984
```

预期：

- `https://localhost:8000/login` 返回 `405` 或正常响应都可以，说明 HTTPS 服务起来了
- `http://localhost:1984` 返回 `200 OK`


### 7.7 看 `micam` 日志

```bash
docker compose logs --tail 80 micam1
```

正常关键字：

- `Login successful`
- `WebSocket connected. Streaming data...`
- `Keyframe detected! Starting stream...`

如果反复出现：

- `Data received timeout`

说明视频数据没有真正收到，需要回头检查网络和防火墙。


## 8. 本次实际修补内容

### 8.1 Docker 运行方式修补

- 放弃 Docker Desktop 接管 Ubuntu 的方案
- 改用 WSL 内原生 Docker Engine
- `docker context` 固定使用 `default`

### 8.2 `docker-compose.yml` 修补

最终使用：

- `miloco`：`host` 网络
- `micam1`：`host` 网络
- `go2rtc`：端口映射

原因：

- 这样更适合当前 WSL mirrored + 原生 Docker 的链路
- 服务间地址也已改到适合当前环境的配置

### 8.3 `Dockerfile.miloco` 修补

已经加入这些关键修补：

- 构建时下载官方 `xiaomi-miloco`
- 默认开启音频
- 默认提高视频质量
- 支持 `MIOT_LAN_TARGETS` 定向扫描摄像机 LAN IP
- 修补 `FastMCP` 参数兼容问题
- 在刷新摄像机列表前主动刷新状态
- 修补前端放大视频弹窗只显示半边的问题

### 8.4 `micam` 修补

修了一个很关键的问题：

- 环境变量 `VIDEO_CODEC` 原来会被 argparse 默认值覆盖
- 导致明明 `.env` 写了，也未必真正生效

当前已修补，`VIDEO_CODEC=hevc` 会正确传入。


## 9. 这次踩过的坑

### 9.1 Docker Desktop 误接管 Ubuntu

现象：

- `docker context ls` 指向 `desktop-linux`
- 容器网络不稳定
- 摄像机一直离线

处理：

- 关闭 WSL Integration
- 退出 Docker Desktop
- `wsl --shutdown`


### 9.2 WSL 不是 mirrored

现象：

- `ip addr` 里是 `172.23.x.x`
- 局域网摄像机相关链路异常

处理：

- 配置 `.wslconfig`
- `wsl --shutdown`


### 9.3 Windows / Hyper-V 防火墙拦截

现象：

- 米家 App 在线
- Miloco 显示离线
- 日志里反复出现 `PPCS_Connect errorcode: -3`

处理：

- 放开 Hyper-V 入站和出站规则


### 9.4 浏览器兼容问题

现象：

- Edge 可能 `解码失败`
- Chrome 缩略图正常，但放大画面只显示一半

处理：

- Edge 优先不用
- Chrome 使用当前已修补的前端版本
- 如果页面没刷新到新资源，执行 `Ctrl + F5`


### 9.5 本机访问地址

现象：

- 同一台 Windows 直接访问 `https://<Windows-LAN-IP>:8000` 不稳定

处理：

- 本机优先用 `https://localhost:8000`
- 局域网其他机器用 `https://<Windows-LAN-IP>:8000`


## 10. 再部署时建议的最短顺序

1. 配好 `.wslconfig`
2. 配好 Hyper-V 防火墙规则
3. 确保 Docker Desktop 不接管 Ubuntu
4. 在 Ubuntu 安装原生 Docker
5. 进入当前项目目录
6. 检查 `.env`
7. `docker compose build miloco`
8. `docker compose up -d`
9. 看 `micam` 日志是否出现 `Keyframe detected! Starting stream...`
10. 打开网页确认摄像机在线
